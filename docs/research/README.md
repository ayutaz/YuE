# 調査: YuE2で特定話者の歌声を再現する

調査日: **2026-09-18** / ブランチ: `research/yue2-singer-voice-lora`

## 目的・ゴール・成果物(2026-09-18 合意)

### 目的

YuE2 で**特定話者(歌手)の歌声を再現するアダプタを作る**。副目標として**日本語対応の品質向上**。

### ゴール(完了の定義)

**主ゴール**: 対象話者の声質に寄った歌唱を YuE2 単体で生成できる状態。判定は3条件すべて:

1. `pyannote/wespeaker-voxceleb-resnet34-LM` のコサインが、素のYuE2ベースラインを
   **leave-one-song-out 全fold平均で上回る**
2. **PER が悪化していない**(声を寄せて歌詞が崩れたら失敗とみなす)
3. **§6 の operating envelope の条件下で**成立する(範囲外は保証しない)

**副ゴール**: 日本語ディクションの PER 改善(4表記の比較で最良の入力形式を確定)

**明示的に除外**: 「本人と聞き間違える」水準(話者照合で本人と判定されるレベル)。
10分固定の条件では到達手段が見えていないため対象外とし、
G0.5(参照音声ICL注入)が想定以上に効いた場合のみ再検討する。

### 成果物

**学習コード + アダプタ重み**。生成した楽曲だけでは完了としない。
達成条件(§ [lora-architecture-and-data-scale](lora-architecture-and-data-scale.md) §6)を
**model card の動作範囲として重みに添付する**。条件抜きで重みだけ配ると範囲外で使われて
「効かない」と評価されるため、条件表は成果物の一部。

### 達成条件の要約

| 種類 | 内容 | 詳細 |
|---|---|---|
| **A: 生成時に守る** | 旋律を実測F0範囲内に拘束(`SongRequest.abc`)/ タグを訓練曲と揃える / 曲は8分未満 / temperature 0.7〜0.85・top_k 30〜50・rep penalty 1.05〜1.1 / 複数シードから選ぶ | § §6.1 |
| **B: データ側の前提** | 声区・強弱・母音×音域セルの被覆、ミックス条件の一貫性。**G0($0)で数値化**。10分固定では埋められないのでAで避ける | § §6.2 |
| **C: 保証しない** | 訓練曲から離れた音域/ジャンル/テンポ、本人判定水準、日本語以外、8分超の一貫性、zero-shot多話者 | § §6.3 |
| **D: 条件は可変** | G0.5 か A が通れば A1/B1〜B3 が緩む。**Bだけ通った場合は何も緩まない** | § §6.4 |

**この条件表は予測であって測定結果ではない。** [コード]で裏付いているのは
「8分」と「`abc`で旋律拘束できること」だけ、[実測]はジャンル一致とサンプリング設定だけで、
残りは [推定]。YuE2単体で特定話者の声を寄せた実証は公式にもコミュニティにも存在しない。

### 実行計画

M0〜M6 の各マイルストーンに目的・ゴール・完了条件・撤退条件を付けたものが
[implementation-milestones.md](implementation-milestones.md)。

| # | マイルストーン | 実行場所 | コスト | 累計 |
|---|---|---|---:|---:|
| **M0** | 評価ハーネスとデータ棚卸し | **ローカル4090** | **$0** | $0 |
| **M1** | 学習基盤の実装(**工数の律速**) | **ローカル4090** | **$0** | $0 |
| **M2** | 参照音声ICL注入の偵察 | **ローカル4090** | **$0** | $0 |
| **M3** | 注入経路の機構学習(他話者データ) | ローカル + 必要ならクラウド | $0〜150 | $0〜150 |
| **M4** | 対象話者への適合 | **ローカル4090** | **$0** | $0〜150 |
| **M5** | operating envelope の実測と model card | クラウド(並列生成) | $40〜120 | **$40〜270** |
| **M6** | 日本語ディクション改善(副目標) | ローカル + クラウド | $50〜200 | **$90〜470** |

**ローカル RTX 4090(24GB)を主環境にしたことで、当初見積り $320〜860 から $90〜470 に下がった。**
学習は S=1,000 × batch 16 で **11.72 GiB**、推論は CFG 2分岐・context上限でも **11.92 GiB** で、
どちらも24GBに倍の余裕がある。クラウドは M5 の並列生成に限定。

**次に着手するのは M0($0)。** M0 と M2 の結果が、M3 以降の設計と難易度を決める。

### まだ決まっていないこと

| # | 論点 | 影響 |
|---|---|---|
| 1 | **日本語対応の位置づけ**(副目標か、声質と同等の主目標か) | 同等ならゲートCを A/B より先に回す |
| 2 | **成功の最終判定者**(話者照合スコアか、ユーザーの耳か) | 耳が最終なら評価ハーネス(G0)の重みを下げられる |
| 3 | **対象話者と権利関係** | 作るものは変わらないが、`MODEL_LICENSE` は権利と同意をユーザー側の責任としており、公開範囲の扱いが変わる |
| 4 | **期間** | フェーズを削るか全部回すかが変わる |

## 結論サマリ

| 問い | 回答 |
|---|---|
| 公式に参照音声でボーカルを指定する機能はあるか | **ない**。`SongRequest` に該当フィールドが無く、音声→semantic tokenエンコーダも未リリース |
| 公式に学習/LoRAの仕組みはあるか | **ない**。本リポジトリは推論専用 |
| コミュニティに「参照音声で声を指定する機能」はあるか | **ない**。あるのは部品(エンコーダ)と、効果が未確認の学習ワークフロー |
| アーキテクチャ的に可能か | **可能**。MoTでAR/NARの重みが層ごとに分離。ただし音色はNAR側にしか入らない |
| 既存実装をそのまま使えば達成できるか | **✗**。MERT identity で stock 0.852 > adapter 0.846/0.847 |
| 独自実装に意味はあるか | **ある**。ただし性質は「既存機能の改善」ではなく**未完成部分の実装** |
| 予算内で収まるか | **大きく余裕がある**。ローカルRTX 4090を主環境にしたことで **$90〜470**(M0〜M6)。§ [implementation-milestones](implementation-milestones.md) |
| 日本語は対応しているか | **している**(公式デモに日本語ボーカル曲あり)。ただし**日本語PERは誰も測っていない** |
| どこに何パラメータのLoRAを差すか | NAR branch(全体の39.4% = 1.409B)。一般論は r=32 / 34.87M / bf16 69.7MB だが、**10分固定の本プロジェクトでは注入0.53M + LoRA r=8/MLPのみ/14層 = 計3.28M**。§ [lora-architecture-and-data-scale](lora-architecture-and-data-scale.md) §2.3 / §4.7.3 |
| 必要なデータ量は(一般論) | 対象話者のクリーンなボーカル **30〜60分・5〜10曲**(最低ライン10分)。コミュニティの実効77〜330秒はこの1/8〜1/5 |
| **手持ち10分で足りるか** | **条件付きで足りる。** ただし10分を学習データではなく**条件入力**として使い、注入経路の機構は**他話者データ(jaCappella等)で学習**する方針に変える。容量は計3.28Mまで絞る。§ [lora-architecture-and-data-scale](lora-architecture-and-data-scale.md) §4.7 |
| 1回の学習にかかる時間と費用は | 3,000ステップが **H100 約20分 / ローカルRTX 4090 約1〜3時間**。試行回数の大半をローカルに寄せられるので**実費はほぼ消える** |
| どこで動かすか | **主環境はローカルの Windows + RTX 4090(24GB)**。学習 11.72 GiB / 推論 11.92 GiB で収まる。README の「Linux」要件はサポート構成の宣言で、POSIX依存は `fast`(vLLM)パスのみ。WSL2 推奨(**未検証**、M0 の冒頭で確認する) |

**到達目標の設定**: 「本人と聞き間違える」ではなく「**声質の傾向と歌い回しが一致し、同一シリーズと認識できる**」レベルに置くべき。
さらに10分固定という実条件では「**訓練曲に近い音域・テンポ・ジャンルの範囲内でなら寄る**」という条件付きの達成に再定義する。
YuE2単独縛りは、現在の公開知見では**未解決問題への挑戦**である。

## 動作・学習環境の前提

- 推論: Linux / Python 3.12 / BF16対応NVIDIA **24GB**(README記載)
- 学習: 長窓・勾配チェックポイント無しなら **80GB級(A100 80GB / H100)が必須**([custom-training-plan.md](custom-training-plan.md) §6.1)。
  ただし **短窓 + 勾配チェックポイントなら約12 GiB** で足りる([lora-architecture-and-data-scale.md](lora-architecture-and-data-scale.md) §3.2)
- **主環境は手元の Windows + RTX 4090(24GB)**。M0〜M4 はローカルで完結する
  ([implementation-milestones.md](implementation-milestones.md) の実行環境節)。
  WSL2 推奨。README の「Linux」要件はサポート構成の宣言で、
  コードレベルの POSIX 依存は `fast`(vLLM)パスのみ(`fast.py:215`/`:220`/`:236`)
- 調査に使った作業機は macOS(darwin)なので、そこでは学習・推論いずれも不可
- **Python は `uv` 経由で実行する**(`python` / `pip` を直接叩かない)。
  `uv venv --python 3.12` → `uv pip install --torch-backend=auto -e .` → `uv run python ...`。
  環境が Windows / WSL2 / クラウドLinux / macOS をまたぐため、インタプリタと依存の解決を uv に寄せる。
  詳細は [implementation-milestones.md](implementation-milestones.md) の実行環境節
