# 実装マイルストーン計画

[README.md](README.md) で合意した目的・ゴール・成果物と、
[lora-architecture-and-data-scale.md](lora-architecture-and-data-scale.md) §5.2 の判断ゲートを、
**実行可能なマイルストーンに落としたもの**。

各マイルストーンには **目的**(なぜやるか)と **ゴール**(何が達成されたら完了か)を
必ず一対で書く。ゴールは**測定可能な形**にし、満たせないときの**撤退条件**も併記する。
撤退条件を書いておかないとゲートが機能せず、予算を溶かす。

## 全体像

| # | マイルストーン | 対応ゲート | コスト | 累計 | 実装の重さ |
|---|---|---|---:|---:|---|
| **M0** | 評価ハーネスとデータ棚卸し | G0 | **$0** | $0 | 中(ローカルのみ) |
| **M1** | 学習基盤の実装 | — | $30〜80 | $30〜80 | **最重** |
| **M2** | 参照音声ICL注入の偵察 | G0.5 | $0〜50 | $30〜130 | 軽 |
| **M3** | 注入経路の機構学習(他話者データ) | A | $80〜250 | $110〜380 | 重 |
| **M4** | 対象話者への適合 | B | $20〜60 | $130〜440 | 軽 |
| **M5** | operating envelope の実測と model card | — | $40〜120 | $170〜560 | 中 |
| **M6** | 日本語ディクション改善(副目標) | C | $150〜300 | $320〜860 | 重 |

- **主目標(M0〜M5)= $170〜560**
- **副目標込み(M0〜M6)= $320〜860** / 予算 $500〜1000 に収まる
- M1 は費用が小さいが**工数が最大**。ここが全体の律速。
- M6 は副目標なので、M5 までの結果と残予算を見て着手を判断する。

### 依存関係

```
M0 ──┬─> M2 ──┐
     │        ├─> M3 ──> M4 ──> M5
     └─> M1 ──┘                  │
                                 └─> M6(残予算で判断)
```

- **M0 は全ての前提**。$0 なので最初に必ず終わらせる
- **M1 と M2 は並行できる**。M2 は学習を伴わないので M1 の完成を待たない
- M2 の結果は M3 の設計を絞り込むが、**M2 が失敗しても M3 は実行する**(§M2 のゴール参照)

## M0. 評価ハーネスとデータ棚卸し

### 目的

以降の**全ての判断の前提となる数値を確定する**。現在 §6.2 の B1〜B4 はすべて [推定] で、
「10分で足りるのか」「どの音域なら使えるのか」が数値になっていない。
また素のYuE2のベースラインを**分散込みで**取らないと、後で改善を主張できない
([community-implementations.md](community-implementations.md) が陥った
「差 0.006 がノイズに埋もれる」状態の再演を避ける)。

### ゴール

以下が**すべて数値として出ている**こと。

| 項目 | 出力形式 |
|---|---|
| 歌唱区間の実効秒数 | 曲ごと + 合計(無音・伴奏のみ区間を除外後) |
| F0 ヒストグラム | 半音ビン。**使用可能音域の上下限**が確定 |
| 母音 × 音域のセル被覆 | 日本語5母音 × 半音ビンの被覆率。**穴の位置が特定されている** |
| 強弱の分布 | ラウドネス(LUFS等)のヒストグラム |
| ミックス条件の一貫性 | 曲間の LTAS / スペクトル重心の差 |
| **stock ベースライン** | 素のYuE2で **10シード以上**生成し、話者照合コサインの**平均と標準偏差** |
| stock の PER | 4パスASRによる PER の平均と標準偏差 |

### 完了条件

1. 上記7項目が数値で出力され、レポートとして保存されている
2. **σ(標準偏差)が出ている**こと。平均値だけでは後続の「+2σ」判定ができない
3. `SongRequest.abc` に渡す旋律を、確定した音域内に収める手順が動く

### 撤退条件

**歌唱区間の実効秒数が 240 秒(4分)を下回った場合**、M3/M4 の見込みが大きく下がる。
その場合は M2(学習なし)に全振りし、M4 の容量をさらに下げる(注入層のみ 0.53M)。

### コストと成果物

- **$0**(ローカル完結。手元の `whisper-large-v3` / `parakeet-tdt_ctc-0.6b-ja` /
  `anime-whisper` / `Qwen3-ASR-1.7B` / `pyannote/wespeaker-voxceleb-resnet34-LM` で足りる)
- ただし **stock ベースライン生成にはクラウドGPUが必要**(作業機は macOS で推論が走らない)。
  10シード × 数分なのでクレジット内に収まる想定
- 成果物: 計測スクリプト群、被覆レポート、ベースライン数値(σ込み)

## M1. 学習基盤の実装

### 目的

**公式が持っていない部分を作る。** YuE2 は推論専用リポジトリで、
`nar_velocity()` は `@torch.no_grad()` 付き・batch=1 前提・attention mask が密行列
([lora-architecture-and-data-scale.md](lora-architecture-and-data-scale.md) §2.5)。
flow-matching の学習ループも存在しない。**ここが全体の最大リスク**であり、
先に「学習が回る」ことを確定させないと M3/M4 の失敗原因を切り分けられない。

### ゴール

**素のモデルで flow-matching loss が意図通り下がる**ことが、
以下の3つのテストで確認されている。

| テスト | 内容 | 合格条件 |
|---|---|---|
| **T1 ゼロ初期化同値性** | zero-init 注入層を挿した状態で推論 | 出力が素のモデルと**数値的に一致**(bit-exact または 1e-5 以内) |
| **T2 単一バッチ過学習** | 1曲の1区間だけを与えて意図的に過学習させる | loss がほぼ 0 まで落ち、その区間の潜在を**再構成できる** |
| **T3 決定性の非破壊** | 学習コードを通した後で通常推論を実行 | 同一シードで同一出力。リポジトリの再現性の作り込み([custom-training-plan.md](custom-training-plan.md) §6.2)を壊していない |

**T2 が最重要。** これが通らない限り、後続で loss が下がらなくても
「実装が悪いのか、手法が悪いのか」が判別できない。

### 完了条件

1. T1 / T2 / T3 がすべて合格
2. 20秒窓 × batch 16 が **約12 GiB に収まる**ことを実測で確認(§3.2 の推定値の検証)
3. 潜在キャッシュ(VAEエンコード結果の事前計算)が動き、再生成手順が文書化されている
4. 設定がシリアライズされ、同一設定から再実行できる(成果物が重みなので再現性は要件)

### 撤退条件

**T2 が通らない状態が続く場合**、`t` のサンプリングが推論側 `_shift_t_value`
(sigmoid + `timestep_shift=1.0`)と整合していない可能性が最も高い。
ここを2回作り直しても通らなければ、**M2(学習なし)の結果だけで
プロジェクトの継続を判断する**。学習基盤が作れなければ成果物(重み)は作れない。

### コストと成果物

- **$30〜80**(デバッグランは短い。1ランが H100 で20分未満、§3.3)
- 成果物: 学習ループ、潜在キャッシュ、T1〜T3 のテスト、設定シリアライザ

## M2. 参照音声ICL注入の偵察

### 目的

**学習を1ステップも回さずに、音色が乗るかどうかを判定する。**
実装は約20行(低レベル関数 `generate_tokens` / `nar.synthesize` を直叩きし、
対象話者の semantic token を AR 文脈に prepend する)。
効けば M3 の学習目標が「機構をゼロから作る」から
「効いた注入の効き方を重みに固定する」に変わり、**M3/M4 のリスクが大きく下がる**。

なお公開APIは prefix を厳格に検証するため(`pipeline.py:277` / `:293`)、
**低レベル関数を直接使う**必要がある。

### ゴール

**「効いた / 効かなかった」がσ付きで確定していること。** どちらでも M2 は完了。

| 結果 | 判定 | M3 への影響 |
|---|---|---|
| 話者照合コサインが M0 のベースライン **+2σ 以上** | **効いた** | M3 の学習目標が「効いた注入を重みに固定する」に変わる。難易度が下がる |
| +2σ に届かない | **効かなかった** | M3 は機構をゼロから学習する。当初計画どおり |

**「効かなかった」は失敗ではない。** M2 の目的は判定であって改善ではない。

### 完了条件

1. 上記判定が **3シード以上**の平均と σ で出ている
2. コミュニティ tokenizer head v9 による対象話者のトークン化が動いている
3. **PER が壊れていないこと**も同時に測る(注入で歌詞が崩れるなら注入位置が悪い)

### 撤退条件

tokenizer head v9 の round-trip(音声→token→再構成)が聴感で別人になる場合、
上流のノイズが支配的で判定にならない(v9 は top-1 一致 18.9% / top-5 45.0%)。
その場合は **M2 を「判定不能」として閉じ、M3 に進む**。M2 に追加投資しない。

### コストと成果物

- **$0〜50**
- 成果物: ICL注入スクリプト、判定レポート(σ込み)、tokenizer head の round-trip 評価

## M3. 注入経路の機構学習(他話者データ)

### 目的

**「参照音声から音色を読む」機構そのものを獲得する。**
この機構の学習には**対象話者のデータを1秒も使わない**(§4.7.2)。
対象話者の10分は 34.87M の LoRA には過剰度 55.9 倍で足りないが、
機構は他話者データで学べるので、10分を「条件入力」として使えるようになる。
**これが10分固定という制約への本質的な回答**。

### ゴール

**学習に使っていない話者で、参照音声を差し替えると出力の音色が変わる**こと。

| 測定 | 合格条件 |
|---|---|
| 未学習話者2名以上で参照を差し替え | 話者照合コサインが**参照した話者の方向に動く**(参照Aで生成 → Aとの類似 > Bとの類似) |
| 伴奏品質 | 生成物の伴奏が崩れていない(§4.5 の領域ミスマッチが出ていない) |
| PER | 素のモデルから悪化していない |

**「対象話者に似たか」はM3では測らない。** ここで測るのは**機構が汎化したか**だけ。

### 完了条件

1. 上記3測定が合格
2. **cross-song ペアリング**で学習している(同一区間ペアだとコピーで loss が下がり音色を学ばない、§2.4)
3. 学習データの規模が実測されている(jaCappella の曲数・総時間は
   HF API の `viewer: false` により未取得のため、ダウンロード時に実測が必要)

### 撤退条件

**未学習話者で参照差し替えが効かない場合**(コサインが参照方向に動かない)、
機構は汎化していない。**注入層を4本から増やす / 層位置を変える**を各1回試し、
それでも動かなければ M3 を閉じて **M4 を「対象話者への直接適合」として実行**する。
その場合 §6.4 の D 表どおり **operating envelope の条件は一切緩まない**ので、
M5 で条件を厳しく記載する。

### コストと成果物

- **$80〜250**(1ランは H100 で1時間未満。費用は試行回数で決まる、§3.3)
- 成果物: 注入経路の重み、学習設定、汎化評価レポート

## M4. 対象話者への適合

### 目的

**対象話者の個別性を入れる。** M3 で獲得した機構の上に、
対象話者10分ぶんの適合を最小容量で載せる。
容量は **注入 0.53M + LoRA r=8 / MLPのみ / 14層 = 計 3.28M**(過剰度 5.3 倍、§4.7.3)。

### ゴール

**README のゴール定義(3条件)を満たすこと。**

| # | 条件 | 測定 |
|---|---|---|
| 1 | 話者照合コサインが stock を上回る | **leave-one-song-out(4〜6 fold)の全fold平均**。単一 held-out・単一シードでは判定しない |
| 2 | PER が悪化していない | 4パスASR。M0 のベースライン ± σ 以内 |
| 3 | §6 の operating envelope 条件下で成立 | A1(音域拘束)/ A2(タグ一致)/ A4(サンプリング)を守った生成で測る |

### 完了条件

1. 上記3条件が LOO-CV で満たされている(4 fold × 600 steps で $0.25、§4.7.6)
2. 窓5秒・ランダムオフセット・600〜1,500 steps で学習している
3. リミックス拡張を適用し、ピッチシフト/フォルマント変換は**使っていない**(§4.7.5)
4. **重みが保存され、M1 の設定シリアライズから再現できる**

### 撤退条件

**LOO-CV 全fold平均で stock を上回れない場合**、容量・step数・層位置を各1回振って再試行。
それでも届かなければ、**M5 で「主ゴール未達」を明記した上で、
達成できた範囲(Lv1 の歌い回しなど)を成果物として確定させる**。
無条件に試行を続けない。

### コストと成果物

- **$20〜60**(データが小さく LOO-CV も安い)
- 成果物: **対象話者アダプタ重み(3.28M)**、LOO-CV レポート、学習設定

## M5. operating envelope の実測と model card

### 目的

**§6 の条件表を「予測」から「測定結果」に変える。**
現在 §6 の条件のうち [コード] 裏付けは A3(8分)と A1 の実施手段だけ、
[実測] はジャンル一致とサンプリング設定だけで、残りは全部 [推定]。
成果物が重みである以上、**条件を知らずに範囲外で使われると「効かない」と評価される**ので、
動作範囲の実測は成果物の一部。

### ゴール

**§6 の A / B / C / D 各条件が実測値で裏付けられ、model card が書ける状態。**

| 条件 | 実測すること |
|---|---|
| A1 音域 | 音域を段階的に外していったとき、**どこでコサインが崩れるか**の境界値 |
| A2 タグ・ジャンル | 一致 / 不一致でのコサイン差(コミュニティの 0.909 vs 0.885 を自分の環境で再測) |
| A3 尺 | 8分超で2チャンクに割ったときの境界での音色ドリフト量 |
| A4 サンプリング | temperature / top_k / rep penalty のグリッドでの最良点 |
| A5 シード | best-of-n の n をいくつにすれば安定するか(n=1,3,8 での成功率) |
| B1〜B3 | M0 の被覆穴の位置と、実際に崩れた位置の**対応** |
| D | M3 が成功したか否かで、A1/B1〜B3 がどれだけ緩んだか |

### 完了条件

1. 上記が数値で出ている
2. **model card が書かれている**: 推奨音域(半音)、推奨タグ、推奨尺、推奨サンプリング設定、
   制限事項(C1〜C5)、ライセンス(CC BY-NC 4.0 の派生物、非商用)
3. §6 の各行の `[推定]` ラベルが `[実測]` に置き換わっている(置き換わらなかった行は明記)

### 撤退条件

なし。**M4 が主ゴール未達でも M5 は実行する**。
「どこまでは効いて、どこからは効かない」を残すことが成果物の価値になる。

### コストと成果物

- **$40〜120**(生成回数が多い。条件数 × シード数で効く)
- 成果物: **model card**、条件別の実測レポート、§6 の更新

## M6. 日本語ディクション改善(副目標)

### 目的

**日本語の歌詞追従(PER)を改善する。** 公式ベンチ(`docs/benchmarks.md`)は
WildSongBench 192プロンプト / 17設定で**言語別内訳を公開していない**ため、
日本語PERは誰も測っていない空白地帯([japanese-support.md](japanese-support.md))。
また `SongRequest` に `phonemes` フィールドが無く、
入力は書記素のまま Qwen BPE に通される。

### ゴール

**4表記(漢字 / ひらがな / カタカナ / ローマ字)の PER 比較で最良の入力形式が確定し、
かつ AR LoRA で PER が素のモデルより改善している**こと。

| 段階 | ゴール |
|---|---|
| **M6a(無料)** | 同一歌詞を4表記で入力して PER を比較。**最良表記が σ 付きで確定** |
| **M6b(学習)** | 日本語ディクション AR LoRA を **full temporal coverage** で学習し、最良表記での PER が M6a を上回る |

**M6a は学習不要**なので、M6b に進まなくても単独で価値がある(運用時の入力形式が決まる)。

### 完了条件

1. M6a: 4表記 × 3シード以上の PER が σ 込みで出ている
2. M6b: AR LoRA が **各シーケンスの全区間を loss に通している**
   (コミュニティ実装の「先頭ウィンドウのみ」欠陥を踏まない、§4.4)
3. 日本語のモーラ処理(っ / ん / ー)がアライメントで壊れていない

### 撤退条件

**M6a で表記間の PER 差が σ 以内**だった場合、入力形式は結果に影響していない。
その場合 M6b の投資対効果が下がるので、**残予算を M5 の条件実測に回す**。

### コストと成果物

- **$150〜300**(M6a は $0〜30、M6b が大半)
- 成果物: 4表記比較レポート、日本語ディクション AR LoRA 重み(M6b まで進んだ場合)

## 予算の配分と打ち切り方針

| シナリオ | 実行範囲 | 費用 |
|---|---|---:|
| 順調(M2 または M3 が効く) | M0〜M5、残予算で M6 | $320〜860 |
| M3 失敗・M4 のみ成功 | M0〜M5(条件を厳しく記載) | $170〜560 |
| M1 が通らない | M0 + M2 で判断を確定させて停止 | $30〜130 |

予算がボトルネックではなく、**M1 の実装工数がボトルネック**(§3.3)。

## まだ決まっていないことの影響

[README.md](README.md) の未確定4件が、この計画に与える影響。

| 未確定 | この計画への影響 |
|---|---|
| 日本語の位置づけ(副目標か主目標か) | **主目標なら M6 を M3 の前に繰り上げる**。M6a は $0〜30 なので M0 と同時でもよい |
| 成功の最終判定者(指標か耳か) | 耳が最終なら M0 の評価ハーネス構築を軽くし、M5 の聴感評価を厚くする |

| 期間 | 短ければ M6 を切る。M0〜M5 は分割不可(M1 を飛ばすと成果物が作れない) |
